# Minimal Boost.Asio WASIp3 support

The application keeps the existing Asio and WebCPP APIs when selecting
`toolset=clang-wasip3`. This increment implements timers and IPv4 TCP/UDP,
including cancellation and composed operations, using Asio's select reactor.
It does not introduce a browser transport for WASI.

The owner approved implementation, local tests, and an AsciiDoc feature matrix.
No CI, publication, or system-wide dependency changes are permitted in this task.

Maintain the Boost changes as a versioned patch against the supported headers.
Apply it to a generated, private include directory, never to the installed Boost.
Reject incompatible inputs rather than silently compiling unpatched headers.
Native and Emscripten builds must keep their existing configuration and behavior.

`threading=single` uses the standard WASIp3 sysroot and disables Asio threads.
`threading=multi` selects the SDK's experimental cooperative threading sysroot.
Threaded builds must preserve synchronization and use a compatible runtime;
they must not silently select the single-threaded implementation. Exception
handling remains a separate choice, subject to the runtimes actually supplied by
the SDK. Unsupported combinations fail with an actionable configuration error.

WASI has no POSIX process signals or interface-name lookup. Unsupported socket
operations return explicit errors. Datagram boundaries must never be changed to
make a buffer sequence compile. Preserve native partial-I/O behavior for streams.
Do not introduce hidden heap allocation merely to emulate scatter/gather I/O.

Local acceptance covers a fresh build of timers, TCP, UDP and cross-thread wakeup;
native controls; exceptions on/off where supported; cancellation; empty datagrams;
multiple buffers; and rejection of unsupported configurations. The feature matrix
lists all existing library feature groups by native, JSPI, Asyncify and WASIp3
variants, distinguishes unavailable from unverified, and links to evidence.
Full Cobalt/WASI integration, POSIX signal emulation, TLS cross-compilation and
implementing all missing libc APIs are subsequent increments, not implicit claims.
