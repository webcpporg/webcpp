# Minimal Boost.Asio WASIp3 Implementation Plan

> Execution: implement directly in this session, with local verification.

**Goal:** Run existing timers and TCP/UDP APIs on WASIp3 and document target capabilities.

**Architecture:** Patch Boost.Asio's POSIX compatibility assumptions while retaining
its scheduler and select reactor. Generate isolated headers for WASIp3 consumers.
Use the SDK's explicit cooperative sysroot for threaded builds.

**Spec:** `docs/superpowers/specs/2026-10-15-asio-wasip3.md`.

## Constraints

- Boost 1.92 is the initial patch baseline; verify inputs before applying it.
- Never modify installed dependencies, generated files by hand, or CI workflows.
- No CI execution, pushes, or publication.
- English files and comments, Portuguese progress updates.
- Preserve callback associations, error propagation and datagram boundaries.

## Review focus

- Empty datagrams must be delivered, unlike zero-byte stream no-ops.
- Multiple UDP buffers must not become several datagrams or silently lose data.
- A thread posting into a blocked context must wake it without polling loops.
- Exception and thread switches must reach every translation unit consistently.
- Unsupported socket operations and SDK combinations must fail explicitly.
